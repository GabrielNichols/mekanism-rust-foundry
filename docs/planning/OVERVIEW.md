# Expanded inventory and in-game validation

Implementation is underway in the [independent Rust laboratory](../../README.md). Its [current status](../../STATUS.md) distinguishes exercised functionality from open qualification gates, and its [contribution guide](../../CONTRIBUTING.md) explains how to extend the work. The rest of this report records the planning review that guides that implementation; its draft templates and planning-time execution counts are not current runtime evidence.

The functional review expanded the plan to **117 families, 253 specific requirements, 138 granular work items and 22 scenario designs**, preserving the initial 106 IDs and traceability to the previous 25 epics. It proposed a Rust engine with a development-only Java bridge for the original runtime. Actual instances were brought forward: login, movement, placement, menus and slots precede the complete processing pilot and networks. Engine TDD, Java characterization and future Java/Rust acceptance have distinct failure/evidence contracts. The planning review itself executed no games, recorded no RED/GREEN cycles and qualified no behavior. The census and expected results depend on the pinned runtime, not documentation counts. See the [inventory](INVENTORY.md) and [roadmap](ROADMAP.md).

## From feature names to verifiable actions

The official-module family counts are Core 94, Generators 11, Tools 6 and Additions 6. Explicit gaps include the Antiprotonic Nucleosynthesizer, Cardboard Box, Chargepad, Dictionary, HDPE Reinforced Elytra, progression, commands, retrogen and Tools effects on mobs. Tag resources support names and nominal surfaces; they do not prove behavior, active IDs or runtime values. Each of the 253 requirements describes actions, observables, boundaries, instances and witnesses. It still needs concrete objects, parameters and captured expected results. The [family data](inventory.json) and [requirements](requirements.json) keep these gaps explicit. Nominal source: [pinned resources](https://github.com/mekanism/Mekanism/blob/a00109e4856fd38b9c5b3dd7f22ce4a59cd65a80/src/datagen/generated/mekanism/assets/mekanism/lang/en_us.json).

## Actual instances in the first vertical increment

The [functional laboratory design](FUNCTIONAL-LAB.md) defines nine topologies: offline contracts, dedicated server, integrated server, dedicated server with one/two clients, independent A/A, observer controls, restart and future Java/Rust comparison. Each job declares processes, scratch directories, world/checkpoint, actors, ports, display, ingress, readiness, phases, limits and evidence. The [22 scenario designs](SCENARIOS.md) include slots, energy starvation, full output, upgrades, restart, networks, security, QIO, multiblocks, radiation, equipment and modules. Clicks must produce server application and updates on every relevant client; a receipt or screenshot alone is insufficient. GameTests, bots and direct calls retain their own proof levels and do not substitute for a real client. See [NeoForge GameTests](https://docs.neoforged.net/docs/1.21.1/misc/gametest/) and [logical/physical sides](https://docs.neoforged.net/docs/1.21.1/concepts/sides/).

## TDD preserves the independent reference

The [TDD contract](TDD.md) requires an independent test, RED for the intended assertion, the smallest actual GREEN and regression checks after refactoring. Failed boot, absent capability or unapplied input blocks the scenario; it is not semantic port RED. Java characterization produces reviewed, sealed expected behavior before Rust gameplay. Mutation controls classify applicability/equivalence, while actual effects and independent witnesses qualify observation beyond the comparator. The [granular roadmap](ROADMAP.md) states dependencies and acceptance for 138 work items. Its 15 historical phases no longer defer all input/GUI work until M11. G8 closes the declared pre-port scope; G9 follows it and requires new Java/Rust evidence.

The planning review's next proposed increment was reference/model contracts, artifact resolution, process supervision and a bridge sufficient for the first real client. The [implementation note](IMPLEMENTATION.md) now links the delivered subset and current evidence. The [instance profiles](instance-profiles.template.json), [reference manifest](profiles.reference.template.json), [JSON backlog](roadmap.json) and [specification](SPECIFICATION.md) remain non-executable drafts wherever bindings, hashes or qualification are missing. [Sources](SOURCES.md) distinguish nominal facts from engineering decisions.
